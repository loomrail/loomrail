# Loomrail 0.1.0-alpha.4

**Status:** release candidate, not yet published
**Date:** 2026-09-01
**Dist-tag:** `next`

This release candidate adds one inbox for every open request that needs the owner's attention. It covers all local
projects without moving workflow state, permissions, budgets, or acceptance decisions out of Loomrail's existing
domain model.

## What changed since alpha.3

- The global `/attention` view and sidebar count include open requests from every registered project.
- Requests are grouped as blocking work, approvals, questions, and manual actions. Within each group, Loomrail uses a
  deterministic priority and age order. The response is limited to 200 items and reports when more items exist.
- An ordinary request uses the same `Answer & resume` command as the Task Cockpit. Acceptance requests open the exact
  project and work item instead of presenting a generic answer action.
- The inbox is rebuilt from durable SQLite workflow records, so it survives a restart without a second inbox table or
  a parallel source of truth.
- The page supports English and Russian, light and dark themes, keyboard selection with Arrow keys, Home, and End, and
  layouts from 320 px through desktop widths.
- The threat model, domain context, product decision record, owner guides, and implementation records now cover the
  global inbox boundary.

## Safety boundary

- The authenticated loopback endpoint aggregates request and project text already stored by Loomrail. It does not
  expose a new unauthenticated route.
- Acceptance still happens in the Task Cockpit. The inbox cannot turn an acceptance request into an ordinary answer.
- Request content is rendered as text. Raw provider payloads are not part of the inbox contract.
- This release does not add operating-system notifications, remote access, cloud sync, or team sharing.

## Known limitations

- This is pre-alpha software. Migration and package upgrade compatibility has not completed a public release cycle.
- The inbox shows at most 200 open items at once. It reports overflow but does not paginate it yet.
- Claiming, snoozing, expiry rules, operating-system notifications, and readiness integration are deferred.
- Claude Code remains outside the write path, and the only built-in project recipe is `typescript-node@1`.
- Desktop packaging, remote access, cloud sync, and mobile control are not included.

## Verification

- `pnpm verify`, 43 browser scenarios, and the production dependency audit passed locally.
- The `0.1.0-alpha.4` tarball installed into an empty directory, reached its readiness endpoint, and served the
  Workbench shell.
- The staged package contains the expected 50 files and no local state database, log, environment file, private key,
  or personal absolute path.
- macOS and Windows CI plus the public registry install will be recorded before publication.

## Install

After publication:

```bash
mkdir loomrail-evaluation
cd loomrail-evaluation
npm install loomrail@next
npx loomrail
```

For a zero-quota first run, open **Settings > AI provider**, choose **Mock**, and then initialize the demo workspace.
The [English quick start](../guides/GETTING-STARTED.md) and
[Russian quick start](../guides/GETTING-STARTED.ru.md) describe the complete route.

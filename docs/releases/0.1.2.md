# Loomrail 0.1.2

**Status:** Candidate; not yet published

**Date:** 2026-09-12

**Intended dist-tag:** `latest`; `next` remains `0.1.0-beta.1`

**Release Support Target:** `MACOS_ARM64` (`darwin/arm64`)

## Changes

- Workspace MCP returns one complete JSON text result instead of duplicate text and structured copies. Digests,
  range/truncation metadata, typed failures, audit and compare-and-set enforcement remain intact.
- Production context excludes optional audit activity with recorded omission provenance. PLAN can receive a
  successful DISCOVERY checkpoint, and IMPLEMENT a successful PLAN checkpoint from the same pipeline. Independent
  REVIEW receives no author checkpoint.
- Initial context uses stage-specific ceilings with durable backoff. Required bytes are never clipped, and an
  over-limit decision-source set now pauses before provider dispatch instead of silently losing old decisions.
- Stable execution guidance asks each stage for relevant bounded reads and compact structured checkpoints while
  keeping every required verification gate.
- The launch form explains expensive tool turns, retries and POST_SESSION overshoot. Session usage shows input,
  output, cached input and uncached input plus output; missing cache attribution remains unknown.

- Stabilizes the optical-alignment E2E test by waiting for dialog entrance animation completion before measuring,
  with unchanged product CSS and spacing tolerances.

## Measurement and limits

The deterministic same-fixture benchmark reduces full Loomrail prompt bytes by 24.14% and modeled cumulative
history bytes by 43.77%. These are UTF-8 bytes, not actual provider tokens. The requested >=50% uncached and >=40%
raw provider-token reductions are not established by that model.

The first real bounded run preserved an honest budget pause after Review. Its incomplete usage is not counted as
full-workflow savings. The owner authorized one additional bounded run before publication; its final sanitized
result is recorded separately in the release evidence.

Provider-owned prefixes, tool-history amplification and statistical forecasting remain areas for further work.
Large required contexts may pause earlier at the new ceiling rather than silently losing authority or evidence.

## Safety and compatibility

All six stages, independent Review, Project verification, measured Browser QA, owner Acceptance, permissions,
audit and durable recovery remain mandatory. Only installed, authenticated local Codex/Claude CLI adapters run in
production. There are no direct provider API routes, API keys, Mock, synthetic success or hidden fallbacks.

Stable live-provider support remains macOS Apple Silicon-only. Windows/Linux dispatch fails closed. No database
migration is added; older binaries may reject the new omission vocabulary, so rollback uses a stopped matching
backup rather than assuming an older binary can read a newer context recipe.

## Verification and publication

See [token-efficiency evidence](../evidence/phase-8/TOKEN-EFFICIENCY-EVIDENCE.md) for the actual before ledger,
deterministic benchmark, tests and failed-run accounting. Exact-source CI, clean-package checks, protected staging,
separate npm approval and registry verification must pass before this candidate is called published.

## Install after publication

```bash
mkdir loomrail-evaluation
cd loomrail-evaluation
npm install --ignore-scripts loomrail@latest
npx playwright install chromium
npx loomrail try
```

Sign in to the official local provider CLI first. Loomrail reuses that local subscription login and does not request
or store the provider credential.

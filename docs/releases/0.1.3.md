# Loomrail 0.1.3

**Status:** Local candidate verified; exact-source CI and publication pending

**Date:** 2026-09-19

**Intended dist-tag:** `latest`; `next` remains `0.1.0-beta.1`

**Release Support Target:** `MACOS_ARM64` (`darwin/arm64`)

## Changes since published 0.1.1

- Includes the [0.1.2 token-efficiency changes](0.1.2.md): single-copy MCP results, bounded stage context,
  structured Discovery/Plan handoffs and honest cache attribution. Actual controlled token savings remain unproven.
- Task activity now keeps earlier runs visible after the pipeline advances. Provider-reported activity is explicitly
  diagnostic and separate from audited workspace operations; it grants no authority and does not enter model context.
- An unknown `LOOMRAIL_PROVIDER` now blocks session admission even when a compatible signed-in CLI is available.
  AUTO still selects a ready local provider; an explicit unavailable choice never silently changes provider.
- Provider-selection regressions use deterministic runtime observations and never depend on developer login state.
- Clean-install verification checks the authenticated runtime version against the package, catching a stale bundle
  even when its manifest and receipt are consistent.
- Public roadmap distinguishes shipped macOS Stable, pending releases and researched future work.

## Compatibility and upgrade

This combined release includes migration `0062` for diagnostic activity. Stop Loomrail and back up the entire local
data directory before upgrading. Rollback uses the matching stopped backup; an older binary is not promised to read
the newer database. No historical migration is rewritten by this patch.

Only installed authenticated local Codex/Claude CLIs run in production; no direct API route, API key, Mock, permission
bypass or automatic publication is introduced. Exact CLI admission remains unchanged. Windows/Linux live execution
remains unsupported and fails closed even when source/package CI passes on Windows.

The proposed code-blind Astra/Fable orchestrator is **not included**. Its design, billing risks and evaluation plan
are recorded in a [separate research report](../research/code-blind-orchestrator-primary-sources.ru.md).

## Verification and publication

Local checks, exact-source six-job CI, package verification, protected staging, separate owner npm approval and
public-registry verification are distinct gates. See the
[readiness plan](../plans/130-repository-release-readiness.ru.md) for scope and recorded results. Until publication
is verified, `latest` remains `0.1.1`; the older pending `0.1.2` stage is not this candidate.

Local `pnpm verify`, full fault-injection, 67 product E2E, 7 protected landing E2E and clean-package verification
passed; production and installed-consumer audits found no known vulnerabilities. The local receipt records a DIRTY
checkout, not a publishable clean-source candidate. A new clean commit/artifact and exact-source CI are still required.

## Install after publication

```bash
mkdir loomrail-evaluation
cd loomrail-evaluation
npm install --ignore-scripts loomrail@latest
npx playwright install chromium
npx loomrail try
```

Sign in to a supported official local provider CLI first. Setup does not start a model session; explicit workflow
Start consumes provider quota under the documented POST_SESSION budget semantics.

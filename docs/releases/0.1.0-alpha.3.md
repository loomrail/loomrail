# Loomrail 0.1.0-alpha.3

**Status:** release candidate, not published
**Date:** 2026-09-01
**Dist-tag:** `next`

This release candidate adds project-level provider selection, explicit local MCP connections, readiness checks, a
read-only plugin SDK, and safe creation of a new local project. The workflow state and owner approval boundaries stay
inside Loomrail rather than provider chat history.

## What changed since alpha.2

- **Provider selection:** each project can use Auto, Codex, Claude Code, or Mock. Auto checks installed CLIs and their
  authentication state. The Settings screen can refresh availability, so ordinary use no longer needs a separate
  `LOOMRAIL_PROVIDER` launch command.
- **Project readiness:** Loomrail scans a registered repository for launch and security evidence, records owner
  attestations, and keeps the resulting decisions through restart.
- **MCP connections:** the daemon owns proposal, consent, capability probe, tool grant, revocation, audit, and process
  recovery. A server cannot become available to a provider without explicit owner approval.
- **Bundled Context7:** the exact server package ships with Loomrail. It can be reviewed and approved from Settings
  without a global install or an `npx` download at startup.
- **Read-only plugin SDK:** local tool authors can import `loomrail/plugin-sdk`. Plugin schemas are checked before the
  plugin enters the ordinary MCP consent and grant flow.
- **New project creation:** Loomrail can render and publish the fixed `typescript-node@1` recipe into an absent local
  directory. The owner reviews the target, file list, content digest, and Git initialization before creation. A marker
  supports exact restart recovery.
- **Documentation:** the English and Russian guides cover providers, MCP, Context7, plugin authoring, readiness, and
  new-project setup.

## Safety boundary

- Auto can select an authenticated live provider and consume its quota. Choose Mock for a deterministic zero-quota
  run.
- Loomrail does not install or authenticate Codex or Claude Code, and it never enables provider permission bypass
  flags.
- Context7 queries leave the machine. Do not send secrets, personal data, or proprietary source code.
- The plugin SDK validates contracts but does not provide operating-system isolation.
- Project creation does not install dependencies, run package scripts, create a commit, add a remote, push, merge, or
  deploy.
- Loomrail binds to loopback. A worktree is task isolation, not a complete security sandbox.

## Known limitations

- This is pre-alpha software. Migration and package upgrade compatibility has not completed a public release cycle.
- Claude Code remains outside the write path.
- The only built-in project recipe is `typescript-node@1`.
- Context7 uses its anonymous service limits; Loomrail does not store a Context7 API key in this release.
- Local plugin discovery, a marketplace, workflow hooks, desktop packaging, remote access, cloud sync, and mobile
  control are not included.
- macOS clean-install verification is complete. Windows CI remains a blocking release check.

## Install after publication

```bash
mkdir loomrail-evaluation
cd loomrail-evaluation
npm install loomrail@next
npx loomrail
```

For a zero-quota first run, open **Settings > AI provider**, choose **Mock**, and then initialize the demo workspace.
The [English quick start](../guides/GETTING-STARTED.md) and
[Russian quick start](../guides/GETTING-STARTED.ru.md) describe the complete route.

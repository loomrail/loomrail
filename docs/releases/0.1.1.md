# Loomrail 0.1.1

**Status:** Stable release candidate for macOS Apple Silicon; not yet published

**Date:** 2026-09-12

**Planned dist-tag:** `latest` (`next` remains on `0.1.0-beta.1`)

**Release Support Target:** `MACOS_ARM64` (`darwin/arm64`)

## Changes

- Admits the exact locally authenticated Codex CLI `0.154.0-alpha.6.2 / darwin / arm64` target after real read-only
  success, typed failure, adapter replay and a complete production workflow through owner Acceptance.
- Keeps allowance reporting independent: no allowance row, semver range, other architecture or platform is inferred
  from execution compatibility.
- Fixes Project verification Acceptance for Plans that combine finite checks with an optional supervised `SERVE`
  recipe. Reservation and Acceptance now bind the same finite recipe set.
- Adds a repeatable public-registry Beta-to-Stable lifecycle gate covering exact installs, setup/Doctor, stopped
  backup, schema-neutral upgrade, matching-version restore and package uninstall without deleting owner data.
- Extends keyboard-first Attention coverage to three simultaneous Projects, including a repository path with spaces
  and Unicode. Existing scheduler limits continue to isolate global, per-Project, per-provider and workspace-writer
  capacity.
- Corrects operations guidance for schema-neutral upgrades and closes superseded implementation-plan statuses.

## Safety boundary

Loomrail still uses only installed, authenticated Codex CLI or Claude Code CLI sessions. There are no provider API
keys, direct provider API routes, Mock, synthetic success, automatic provider login/update, hidden fallback or
automatic Git publication. Workflow state, permissions, budgets, verification, QA and Acceptance remain owned by the
deterministic Loomrail domain.

Stable support remains limited to macOS Apple Silicon. Windows and Linux live-provider dispatch stays unsupported and
fails closed. A worktree isolates collisions but is not an operating-system sandbox.

## Install after publication

```bash
mkdir loomrail-evaluation
cd loomrail-evaluation
npm install --ignore-scripts loomrail@latest
npx playwright install chromium
npx loomrail try
```

Sign in to the official local provider CLI first. Loomrail reuses that local subscription login and does not request
or store the provider credential.

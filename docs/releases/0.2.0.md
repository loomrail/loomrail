# Loomrail 0.2.0

**Status:** Candidate; not published

**Date:** 2026-09-21

**Dist-tag:** `latest` on publication; `next` remains `0.1.0-beta.1`

**Release Support Target:** `MACOS_ARM64` (`darwin/arm64`)

This is a minor release rather than a patch: it adds an opt-in execution mode that did not exist in `0.1.3`.

## Changes since published 0.1.3

- **An opt-in code-blind planning coordinator.** A separate PLAN profile plans from an owner-authored product
  outcome and closed progress facts alone. It receives no repository, workspace, network, MCP, source, paths, diffs,
  tool output, transcripts, Decisions or Constitution, and holds only `ARTIFACT_WRITE`. Luna/Sonnet workers own every
  repository action. All six deterministic stages, independent Review, measured Project verification, Browser QA and
  final human Acceptance stay mandatory, and its typed work orders are a plan for a worker rather than completed
  work. The mode is off by default, is chosen before Start, and cannot be changed afterwards.
  See [ADR-0035](../adr/0035-code-blind-coordinator.md), PD-035 and the
  [T88 threat-model delta](../security/THREAT-MODEL.md).
- **Exact execution admission for Codex CLI `0.155.0-alpha.9.2 / darwin / arm64`,** after an owner-authorized native
  qualification that completed all six stages, restart recovery and owner Acceptance. Allowance reporting, adjacent
  versions, other architectures and Windows/Linux inherit nothing from that evidence and keep failing closed.
- **Read-only Discovery no longer asks for write authority.** The prompt and the Structured Output contract now state
  that work a later stage will need is not a blocker for a read-only stage, after a qualification run stalled in
  exactly that way. Both provider-visible surfaces carry regression coverage.
- **Narrower session-loop reads.** Session bookkeeping selects attempt metadata and scalar gate, session, usage and
  activity counters instead of full workflow, checkpoint, recipe and activity projections. This isolates coordinator
  session preparation and execution; it is not a claim that the daemon as a whole never loads product state.
- Dependencies: React and React DOM to 19.3.0, `@tanstack/react-router` to 1.170.36.

## Compatibility and upgrade

This release adds **no database migration**; `0062` from `0.1.3` remains the latest. Stage assignments gain additive
optional fields, so existing records are read unchanged — but a record the coordinator writes is not promised to be
readable by an older binary. Stop Loomrail and back up the entire local data directory before upgrading; rollback
uses the matching stopped whole-directory backup.

Only installed authenticated local Codex and Claude Code CLIs run in production. No direct provider API route, API
key, Mock adapter, permission bypass or automatic publication is introduced. Windows and Linux live-provider
execution remain unsupported and fail closed even though source, browser and package CI pass on Windows.

The coordinator is explicitly **experimental**. It is pinned to CODEX / `gpt-6-astra` with no alias or model
fallback, and Fable is neither qualified nor substituted. Token savings and quality non-inferiority are **not
measured**: one paired smoke observation showed 12,128 → 6,902 input tokens after ambient-context restrictions,
which is not a full-task saving or a quality claim. Its 12,000-token planning ceiling is post-session accounting,
not a promise to stop generation exactly at that boundary.

## Verification

Exact source passed all six macOS/Windows CI jobs — both Verify, both Browser smoke and both Clean install — and a
full local `pnpm verify`. The stable release gate reports 9/9 required gates for `MACOS_ARM64`, with both Windows
live-provider rows deliberately `PENDING`. Sanitized coordinator evidence, including the negative first
qualification attempt and its authorized-ceiling overrun, is recorded in the
[coordinator evidence](../evidence/phase-8/CODE-BLIND-COORDINATOR-EVIDENCE.md) and
[plan 133](../plans/133-code-blind-orchestrator.ru.md).

Two `provider-codex` allowance-reader tests were repaired in this release rather than the code they cover: each
fixture spawns a real `node`, and their read deadlines were short enough that a loaded host lost the race, so they
failed while the reader behaved correctly. The escalation test now proves the grace-period branch from the signal
the child records instead of from wall-clock timing.

`0.1.3` remains the published Stable release until this candidate completes exact-source CI, package verification,
protected-environment review and separate owner npm approval. Staging is not publication.

## Install

```bash
mkdir loomrail-evaluation
cd loomrail-evaluation
npm install --ignore-scripts loomrail@latest
npx playwright install chromium
npx loomrail try
```

Sign in to a supported official local provider CLI first. Setup does not start a model session; explicitly starting
a workflow consumes provider quota under the documented POST_SESSION budget semantics.

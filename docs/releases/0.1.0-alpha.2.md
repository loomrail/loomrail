# Loomrail 0.1.0-alpha.2

**Status:** published to npm
**Date:** 2026-08-30
**Dist-tag:** `next`

This pre-alpha checkpoint makes an existing repository legible to Loomrail before the first live run and replaces the
public landing with a product-led, bilingual experience built around the real Workbench and a safe local start.

## What changed since alpha.1

- a bounded, read-only repository scan proposes all seven Project Constitution sections with source attribution;
- owners can review the proposal, adopt it explicitly and publish `.loomrail/constitution.md` without overwriting an
  owner-edited target;
- repository onboarding state and audit events persist through restart and expected-version conflicts;
- the public landing now leads with a real Workbench capture, a complete safe-start command and an explicit
  «available / not claimed» alpha boundary;
- the README and user documentation now share one project-local installation route and keep internal plans out of the
  public product path;
- English and Russian copy, light/dark themes and the documentation index now have equal acceptance coverage;
- the release dependency inventory now follows every runtime workspace package, including live providers, workspace
  operations and Project Constitution.

## Included product route

- a single `loomrail` launcher package for macOS and Windows;
- a loopback-only daemon, one-time browser bootstrap and local SQLite state;
- durable Discovery → Plan → Implement → Review → QA → Acceptance workflows;
- typed Human Requests, budgets, recovery Decisions, change evidence and owner acceptance;
- deterministic mock-first evaluation, live Codex execution and read-only Claude Code stages;
- repository registration, per-task worktrees and owner-approved Project Constitution publication.

## Known limitations

- This is a pre-alpha: migrations and package upgrades have not completed a public compatibility cycle.
- Loomrail never commits, pushes, merges, deploys or publishes repository changes automatically.
- Claude Code is not on the write path.
- A worktree is task isolation, not a complete operating-system sandbox.
- There is no desktop package, remote access, cloud sync, mobile control, plugin SDK or product BrowserDriver.
- Linux is best effort; macOS and Windows are the blocking release platforms.

## Install

```bash
mkdir loomrail-evaluation
cd loomrail-evaluation
npm install loomrail@next
npx loomrail
```

The default provider is deterministic mock. It does not start Codex or Claude Code and does not consume provider
quota. Continue with the [English](../guides/GETTING-STARTED.md) or
[Russian](../guides/GETTING-STARTED.ru.md) quick start before connecting a live provider.

# Loomrail 0.1.0-beta.1

**Status:** selected Public Beta candidate; publish evidence pending

**Date:** 2026-09-11

**Dist-tag:** `next` (`latest` remains unchanged)

**Supported live-provider target:** macOS Apple Silicon (`darwin/arm64`)

## What is ready

- Local authenticated Codex CLI and Claude Code CLI run all six workflow stages without provider API keys or
  separate API billing.
- IMPLEMENT receives only bounded, permission-checked workspace file operations and owner-approved verification
  recipes through Loomrail's provider-neutral executor. QA remains read-only.
- Workflow state, budgets, gates, audit, dependency order, measured Project verification, Browser QA and final
  Acceptance remain domain-owned and durable across restarts.
- A three-WorkItem private Recurkit Epic completed with both providers, an actual failed verification/correction loop,
  cross-provider Review, measured Browser QA and owner Acceptance.
- Guided activation, diagnostics, backup/restore guidance, redacted local logs, private Insights, dependency policy,
  release receipts and clean-package verification are included.
- Environment-bound Guided Deploy can dispatch only fixed owner-approved Preview/Production GitHub Actions workflows;
  Production requires matching successful Preview evidence. No automatic deploy, retry, probe or rollback exists.

## Platform boundary

Live Codex CLI `0.153.4` and Claude Code CLI `2.1.260` execution is verified on `darwin/arm64`. Windows source,
browser, process-lifecycle and clean-package CI is green, but real Windows local-CLI execution has not been captured.
Windows and Linux provider dispatch therefore fails closed and this Beta does not claim support for them. There is no
Mock, direct OpenAI/Anthropic API route, token credential or synthetic fallback.

## Safety and limitations

- A worktree is collision isolation, not an operating-system sandbox. Providers run as the local user and may receive
  network permission only when the exact run policy grants it.
- Provider token usage is `POST_SESSION`: time, turns, tool calls and output are bounded, while an individual provider
  turn can exceed its token estimate before terminal usage arrives.
- Loomrail does not automatically commit, push, merge, deploy, update itself or accept delivery.
- Desktop packaging, remote access, cloud sync, team accounts and Windows/Linux live-provider support are not in this
  Beta.
- Database migrations are forward-only. Back up the entire Loomrail data directory before upgrading; rollback means
  restoring that matching backup with the earlier package version.

## Install after publication

Use a new empty directory on macOS Apple Silicon:

```bash
mkdir loomrail-evaluation
cd loomrail-evaluation
npm install --ignore-scripts loomrail@next
npx playwright install chromium
npx loomrail try
```

Sign in first with `codex login` or `claude auth login`. Loomrail reads only readiness facts and never asks for the
provider credential.

## Publication proof

The final source commit, CI run, Pages run, npm integrity/provenance, clean registry installation and GitHub
prerelease URL will be recorded here only after those external operations succeed. A local tarball or staged npm
candidate is not a public release.

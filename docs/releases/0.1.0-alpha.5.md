# Loomrail 0.1.0-alpha.5

**Status:** release candidate
**Date:** 2026-09-02
**Intended dist-tag:** `next`

The candidate is not tagged or published. Its source commit must be the clean trusted-workflow commit recorded by the
release receipt and future registry provenance; no earlier hash in this document authorizes publication.

This release candidate carries the post-alpha.4 orchestration, independent review, deterministic QA, acceptance
export, operational diagnostics, guided setup, crash recovery, and release-integrity slices. None moves workflow or
release authority into a provider, browser, in-memory worker, or unsigned receipt.

## What changed since alpha.4

- Loomrail can run up to three independent AgentRuns concurrently by default. Global, Project, provider, and
  workspace limits are validated and checked again inside the SQLite transaction that reserves each run.
- A versioned AgentProfile and immutable SquadAssignment now identify the exact role assigned to every executable
  workflow stage. ProviderSession remains a shorter provider-native session inside one durable AgentRun.
- The scheduler uses stable priority and creation order, bounded inputs, stable-checkpoint checks, and closed deferral
  reasons. It is advisory; persistence owns the final claim.
- The daemon uses a bounded pool, fills a released slot without polling, captures the exact adapter chosen for a run,
  and aborts every live provider session on shutdown.
- **Agent Fleet** shows Task, Project, role, stage, provider, running/ready/waiting status, and the exact capacity,
  checkpoint, or workspace reason behind a wait. It is reconstructed from durable state after reconnect or restart.
- Fleet supports English and Russian, equal light and dark states, native keyboard navigation, and a stacked layout at
  320 px. It cannot grant permissions, raise budgets, answer Human Requests, or make acceptance decisions.
- Migration 20 adds AgentRun and SquadAssignment storage while preserving older ProviderSession history without a
  fabricated backfill.
- Independent Review uses a distinct reviewer AgentRun, exact tree binding, bounded rounds, and owner-only finding
  dispositions.
- Deterministic Browser QA stores measured executions, observations, screenshots/traces, and exact tree provenance.
  Failed QA enters a bounded correction/review/retest loop; provider prose cannot waive a defect or create passing
  evidence.
- Acceptance criteria bind to current Review/QA checks. The owner can download an escaped, bounded, read-only
  acceptance summary without exposing attachment storage keys or repository paths.
- `loomrail doctor [--json]` inspects runtime, Git, storage, SQLite/migrations, and provider availability without
  starting or mutating the daemon. `loomrail data-path` separately reveals the exact local storage path.
- `loomrail setup` adds a guided zero-write Mock/Live preflight. It checks Doctor, Chromium, provider readiness and
  environment-override conflicts, then returns only closed status and owner actions; automation uses explicit mode
  and deterministic JSON.
- Live provider admission now observes a bounded exact CLI version before authentication. Only an exact verified
  matrix row can become ready; Doctor and Project Settings expose normalized closed compatibility states. The initial
  live allowlist is intentionally empty, so Auto uses Mock and explicit live choices fail before spawn.
- The named 486-test crash/fault gate kills a test-owned daemon during a durable ProviderSession and proves exactly
  one interruption report with no automatic replay after two restarts.
- Release packaging emits a closed integrity receipt with tarball and per-file digests. Clean install verifies the
  receipt, installs with dependency scripts disabled, audits the consumer graph, and then launches the package.
- Repository dependency resolution now enforces strict release age, publisher-trust no-downgrade, lockfile recheck,
  blocked exotic transitives, and reviewed lifecycle-script permissions.
- The production launcher now writes only pre-persistence-redacted, bounded operational NDJSON. It rotates 2 MiB
  segments under a 16 MiB/30-day policy; `loomrail logs export` re-redacts a complete snapshot and `logs delete`
  removes exact owned segments only while the daemon is stopped.
- Both bundled Project templates are dependency-free tested repositories with two exact Task recipes each. A public
  EN/RU catalog documents the one shipped workflow, actual standard role mapping, and owner-only acceptance boundary.
- The public repository includes structured bug and product-proposal forms, an enabled private vulnerability route,
  disabled blank external issues, and an outcome-ordered roadmap without calendar promises.

## Safety boundary

- Provider processes start only after the durable AgentRun and workspace claim commit.
- A provider handoff stays inside one AgentRun and does not consume another slot.
- An interrupted run is recorded as interrupted on restart and is never retried automatically.
- Role playbooks can refine context but cannot remove required workflow sections or expand permissions.
- Fleet is an authenticated bounded projection. It does not expose raw provider output or become a second queue.
- Operational logs are diagnostics rather than Events or acceptance evidence. Raw provider stdout/stderr remains
  unrecorded, and no log management route is exposed over HTTP.
- A successful `--version`, upstream release, setup run, or semver range cannot promote provider compatibility.
  Promotion requires reviewed real-stream recordings and matching macOS/Windows evidence for one exact version.

## Known limitations

- This remains pre-alpha software. Public migration and upgrade compatibility has not completed a stable release
  cycle.
- Scheduling limits currently use validated daemon configuration; a user-facing concurrency editor is deferred.
- The first squad assignment follows the fixed Standard workflow. User-imported roles, provider-native subagents, and
  a dependency graph editor are not included.
- Cost controls use the budget data providers can report; this release does not claim complete hard spend governance.
- Desktop packaging, remote access, cloud sync, team accounts, and automatic Git publishing are not included.
- Registry provenance is required for a future stable release but does not exist for this unpublished candidate.
  Private dogfood and the complete stable-release exit gate remain open.
- No Codex or Claude Code version has a verified live matrix row in this candidate. Mock is the only admitted route
  until a separately owner-authorized, quota-bearing promotion slice is complete.

## Install after publication

```bash
mkdir loomrail-evaluation
cd loomrail-evaluation
npm install --ignore-scripts loomrail@next
npx loomrail
```

For a zero-quota first run, open **Settings > AI provider**, choose **Mock**, and then initialize the demo workspace.

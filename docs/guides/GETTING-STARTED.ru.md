# Быстрый старт Loomrail

> Публичный pre-alpha · [English version](GETTING-STARTED.md) · [Полное руководство](USER-GUIDE.ru.md)

Это самый короткий безопасный путь от пустого каталога до сохранённой mock-поставки. Codex и Claude Code не
запускаются, provider quota не расходуется.

## Требования

- Node.js `>=24.19 <25`
- macOS или Windows; Linux работает в best-effort режиме
- браузер на той же машине

## 1. Установите и запустите

Локальная установка оставляет выбранную pre-alpha версию явной:

```bash
mkdir loomrail-evaluation
cd loomrail-evaluation
npm install loomrail@next
npx loomrail
```

Launcher слушает только loopback и открывает одноразовую авторизованную ссылку. Не закрывайте терминал. Чтобы не
открывать браузер автоматически, запустите `npx loomrail --no-open --port 4176` и откройте напечатанную ссылку на той
же машине в течение 60 секунд.

Если нужен глобальный бинарник в `PATH`:

```bash
npm install -g loomrail@next
loomrail
```

## 2. Пройдите mock-маршрут

1. Выберите **Инициализировать demo-пространство**.
2. Создайте задачу с конкретным brief и наблюдаемыми критериями приёмки.
3. Переместите её в **Готово к работе**, затем нажмите **Запустить процесс**.
4. Ответьте на блокирующий Human Request.
5. Одобрите явное увеличение mock-бюджета, когда маршрут остановится.
6. Проверьте evidence Review и QA, затем примите поставку или верните её в работу как владелец.

Reload страницы и restart Loomrail не удаляют задачу, запрос, Decision, budget, evidence или acceptance. Остановите
Loomrail сочетанием `Ctrl+C`.

## 3. Подключите свой репозиторий

Откройте **Настройки → Проекты → Подключить локальный репозиторий** и укажите абсолютный путь к корню Git-репозитория.
Затем откройте **Конституцию проекта**:

1. запустите ограниченное read-only сканирование;
2. проверьте все семь предложенных разделов и подписи источников;
3. примите proposal только если он соответствует репозиторию;
4. проверьте опубликованный `.loomrail/constitution.md` в репозитории.

Scan читает только разрешённые metadata и документацию. Loomrail не пишет Constitution до явного принятия и не
перезаписывает файл, изменённый владельцем.

Перед живым запуском прочитайте [раздел о репозитории и worktree](USER-GUIDE.ru.md#4-регистрация-своего-репозитория) и
[threat model](../security/THREAT-MODEL.md). Worktree изолирует задачи друг от друга, но не является OS sandbox.

## 4. Подключите живого provider

Самостоятельно установите и авторизуйте CLI provider, затем перезапустите Loomrail с явным adapter:

```bash
LOOMRAIL_PROVIDER=CODEX npx loomrail
```

Codex сейчас обслуживает все шесть стадий. Claude Code обслуживает только Discovery, Plan и Review; на неподдерживаемой
стадии Loomrail открывает Human Request, а не переключает provider молча. Loomrail не commit-ит, не push-ит, не
merge-ит и не deploy-ит изменения агента.

Продолжите по [полному руководству](USER-GUIDE.ru.md), чтобы проверить изменения, recovery после restart, backup
состояния и troubleshooting, или используйте [воспроизводимый full-route пример](../examples/full-route/README.md).

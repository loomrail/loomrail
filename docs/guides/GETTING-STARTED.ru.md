# Быстрый старт Loomrail

> Публичная pre-alpha · [English version](GETTING-STARTED.md) · [Руководство владельца](USER-GUIDE.ru.md)

Это самый короткий безопасный путь от пустого каталога до сохранённой mock-поставки. Он не запускает Codex или Claude
Code, не затрагивает существующий репозиторий и не расходует квоту провайдера.

## Требования

- Node.js `>=24.19 <25`
- macOS или Windows; Linux работает в режиме best effort
- браузер на той же машине

Перед установкой проверьте Node.js:

```bash
node --version
```

## 1. Установите и запустите

Создайте отдельный каталог для проверки. Не начинайте внутри важного репозитория.

```bash
mkdir loomrail-evaluation
cd loomrail-evaluation
npm install loomrail@next
npx loomrail
```

Тег `next` явно выбирает публичный pre-alpha канал. Launcher слушает только `127.0.0.1`, открывает одноразовую
авторизованную ссылку и использует детерминированный провайдер `MOCK`, пока вы явно не выберете другой. Не закрывайте
терминал.

Чтобы браузер не открывался автоматически:

```bash
npx loomrail --no-open --port 4176
```

Откройте напечатанную ссылку в браузере на той же машине в течение 60 секунд. Флаг `--no-open` не включает удалённый
доступ.

Если нужен глобальный бинарник, выполните `npm install -g loomrail@next`, а затем `loomrail`. Для проверки продукта
рекомендуется локальная установка выше: выбранный pre-alpha канал остаётся явным.

## 2. Пройдите mock-маршрут

1. Выберите **Инициализировать demo-пространство**.
2. Создайте задачу с конкретным результатом и наблюдаемыми критериями приёмки.
3. Переместите её в **Готово к работе**, затем нажмите **Запустить процесс**.
4. Ответьте на блокирующий Human Request.
5. Одобрите явное увеличение mock-бюджета, когда маршрут остановится.
6. Проверьте доказательства Review и QA, затем примите поставку или верните её в работу.

Перезагрузка страницы или Loomrail не удаляет задачу, запрос, Decision, бюджет, доказательства и решение о приёмке.
Остановите Loomrail сочетанием `Ctrl+C` и дождитесь выхода команды.

## После первого запуска

Перед регистрацией репозитория или включением живого провайдера прочитайте
[руководство владельца](USER-GUIDE.ru.md). Там описаны проверка Конституции проекта, worktree задачи, просмотр
изменений, восстановление, резервное копирование и решение проблем. Перед доступом агента к чувствительному коду
прочитайте [модель угроз](../security/THREAT-MODEL.md): worktree разделяет файлы задач, но не является sandbox ОС.

# Руководство пользователя Loomrail

> Ранний pre-alpha · [Быстрый старт](GETTING-STARTED.ru.md) · [English version](USER-GUIDE.md)

Это руководство проводит от чистого локального запуска до принятой поставки, а затем объясняет, как запустить
настоящего coding-агента, проверить его работу, восстановиться после рестарта и сохранить локальное состояние
Loomrail.

Loomrail работает локально, но не является security sandbox или полноценным Git-клиентом. Живой агент запускается с
правами вашей учётной записи ОС и может использовать сеть. Loomrail создаёт для задачи отдельный Git worktree,
показывает изменения и хранит состояние workflow, но не commit-ит, не push-ит и не merge-ит результат агента.

## 1. Установка и запуск

Используйте Node.js `>=24.19 <25`. Для первого запуска установите явный публичный pre-alpha канал в отдельный пустой
каталог, а не внутрь важного репозитория:

```bash
mkdir loomrail-evaluation
cd loomrail-evaluation
npm install loomrail@next
npx loomrail
```

Тег `next` оставляет pre-alpha канал явным. Чтобы добавить launcher в `PATH`:

```bash
npm install -g loomrail@next
loomrail
```

Loomrail занимает свободный loopback-порт и открывает Workbench в браузере по умолчанию. Чтобы не открывать браузер
автоматически:

```bash
npx loomrail --no-open --port 4176
```

При глобальной установке используйте те же флаги: `loomrail --no-open --port 4176`.

Откройте напечатанную одноразовую ссылку в браузере **на той же машине** в течение 60 секунд. Она авторизует один
браузер, после чего перестаёт работать. `--no-open` не включает remote mode: daemon по-прежнему слушает только
loopback.

Для запуска из исходников используйте `pnpm dev` в репозитории. Это путь контрибьютора: перед стартом он собирает весь
workspace.

Не закрывайте терминал. Закрытие вкладки не останавливает Loomrail или его очередь. Для штатного завершения нажмите
`Ctrl+C` в терминале и дождитесь выхода команды.

## 2. Какой provider работает

Provider выбирается для Project. Выберите проект и откройте **Настройки → ИИ-провайдер**:

| Выбор       | Что происходит                                                                                                            |
| ----------- | ------------------------------------------------------------------------------------------------------------------------- |
| Авто        | Используется установленный CLI с активным входом. Если такого нет, новые сессии получают явно обозначенный Mock fallback. |
| Mock        | Детерминированный test double. Внешний агент не запускается; доступны все шесть стадий.                                   |
| Codex       | Настоящий CLI `codex` работает в Git worktree задачи на всех шести стадиях.                                               |
| Claude Code | Настоящий CLI `claude` обслуживает Discovery, Plan и Review. Неподдерживаемая стадия останавливается на Human Request.    |

Установите Codex или Claude Code и авторизуйтесь через собственный CLI провайдера, затем запускайте Loomrail обычной
командой. После установки или входа нажмите **Проверить снова**. Loomrail проверяет только наличие executable и код
завершения status-команды; credentials и текст её ответа не сохраняются. Если готовы оба живых CLI, Авто выбирает
provider с более широким покрытием стадий. Изменение относится к новым provider sessions; уже запущенная сессия
остаётся на прежнем adapter.

Если явно выбранный живой provider не установлен или не авторизован, Loomrail откажет заметно, а не подменит его Mock.
Даже если вы собираетесь использовать Codex, сначала выберите **Mock**: так можно проверить установку, browser
authentication, persistence, Human Requests, бюджеты и acceptance без расхода provider quota.

`LOOMRAIL_PROVIDER=MOCK|CODEX|CLAUDE_CODE` остаётся необязательным, чувствительным к регистру process-wide override для
автоматизации и диагностики. Он блокирует Project selector до перезапуска. Неизвестное значение показывается как
ошибка и оставляет процесс в Mock-режиме. В обычном запуске эта переменная не нужна.

## 3. Первая mock-поставка

### Проект и задача

1. В пустой установке выберите **Инициализировать demo-пространство**. Loomrail скопирует два встроенных шаблона в
   data directory и создаст для них настоящие локальные Git-репозитории.
2. Выберите проект и нажмите **Новая задача**.
3. Запишите название и brief: ожидаемый результат, ограничения и относящиеся к работе файлы. Выберите приоритет и
   создайте задачу.
4. Откройте задачу и через **Редактировать задачу** добавьте по одному критерию приёмки на строку. Лучше описывать
   наблюдаемый результат, а не способ реализации.
5. Нажмите **Переместить в «Готово к работе»**, затем **Запустить процесс**.

Кнопка запускает один и тот же ограниченный шаблон Discovery → Plan → Implementation → Review → QA → Acceptance для
любого provider. С provider по умолчанию детерминированные результаты стадий даёт mock; с Codex работают настоящие
сессии.

### Параллельная работа в «Агентах»

Откройте **Агенты** в sidebar, чтобы увидеть агентскую работу во всех локальных Project. Каждая строка показывает
Task, Project, назначенную versioned-роль, stage, provider и состояние **В работе**, **Готов** или **Ожидает**. Для
ожидающей строки указана точная причина планировщика: общий, Project- или provider-limit, нестабильный checkpoint либо
конфликт workspace. Название Task возвращает в её Task Cockpit.

По умолчанию Loomrail одновременно выполняет не более трёх AgentRun. «Агенты» — read-only проекция durable queue и
run state, а не второй scheduler: reload страницы или restart Loomrail восстанавливает её из SQLite. Здесь нельзя
выдать permission, поднять budget, ответить на Human Request или принять поставку — эти действия остаются в своих
owner gates.

### Независимое ревью

После Implementation Loomrail запускает новый AgentRun роли **Code reviewer** над зафиксированным Git tree. При
**Auto** и двух готовых live CLI стадия Review предпочитает provider, которым не выполнялся последний Developer run.
Явный выбор provider для Project остаётся lock: Task Cockpit честно показывает **Тот же provider**, но reviewer всё
равно работает в отдельном запуске.

Task Cockpit показывает раунд, verdict, связь providers, проверенный tree и ограниченный список findings с severity,
portable file/line location и шагами воспроизведения. `PASSED` переводит работу в QA. Первый
`CHANGES_REQUESTED` ставит в очередь второй Implementation и новое Review. После второго появляется Human Request:
владелец может разрешить ровно один финальный bounded fix/re-review либо отменить run. Если финальное ревью снова
требует правок, четвёртый dispatch не создаётся.

Только владелец может отметить открытое замечание как **Риск принят** или **Ложное срабатывание**, обязательно указав
причину. Решение попадает в audit и переживает restart; оно не превращает автора в собственного reviewer и не
обходит повторное ревью незаметно.

### Ответ на Human Request

Mock-стадия Discovery открывает блокирующий вопрос, а задача получает статус **Ждёт вас**. Откройте **Внимание** в
sidebar: там собраны открытые запросы всех Project с задачей, стадией, приоритетом и безопасным действием. Клавиши
Arrow Up, Arrow Down, Home и End перемещают выбор. Выберите вариант и нажмите **Ответить и продолжить**. Задача и её
баннер остаются альтернативными входами в ту же форму ответа.

Запрос, ответ и возникшее Decision сохраняются надолго. Reload страницы или restart Loomrail не удаляет вопрос без
ответа. Глобальный список показывает не более 200 items и сообщает, если есть продолжение. Это проекция durable
workflow state, а не вторая очередь: ответ в любом месте закрывает тот же HumanRequest и создаёт одно Decision.

### Остановка по бюджету

На стадии Implementation mock достигает заданного лимита оценочных токенов и переходит в статус
**Остановлен лимитом**.
Проверьте расход и используйте предложенное действие **Одобрить лимит … токенов**, если workflow должен продолжиться.

Override создаёт новую ревизию budget policy и не переписывает прошлый расход. Другие hard pause — например, provider
отклонил вход или не сделал прогресса — не показывают бесполезную кнопку бюджета. Продолжайте через их Human Request.

Во время работающей стадии **Приостановить** запрещает Loomrail планировать дальнейшую работу. **Продолжить** доступно
для soft pause или прерванного запуска. **Отменить запуск** завершает текущий run, поэтому используйте его только когда
действительно хотите остановить маршрут.

### Решение Acceptance

После Review и QA карточка показывает **Пакет приёмки**: типизированные evidence и матрицу критериев. Проверьте их и
выберите действие владельца:

Приёмка также появляется во **Внимании**, но на неё нельзя ответить как на обычный Human Request. Нажмите **Перейти к
приёмке**, чтобы перед решением открыть точные Project и задачу.

- **Принять результат** переводит задачу в Done;
- **Вернуть в работу** фиксирует необходимость ещё одного прохода;
- **Отклонить** фиксирует отклонённую поставку.

Принятая задача исчезает из Active. Чтобы снова её увидеть, откройте **Все задачи**. Loomrail сохраняет решение, но
по-прежнему не commit-ит и не публикует содержимое репозитория.

## 4. Создание или регистрация репозитория

### Создайте новый проект

Откройте **Настройки → Проекты → Создать новый проект** и укажите абсолютный путь с существующим parent, финального
каталога которого ещё нет. До подтверждения нажмите **Проверить точные файлы**. Review связывает canonical target,
версию встроенного recipe `typescript-node`, digest каждого файла и общий digest предложения. Действие **Создать этот
проект** затем создаёт только эти файлы с create-new semantics, добавляет `.loomrail/scaffold.json`, инициализирует Git
без пользовательских templates/hooks, проверяет результат и выбирает Project.

Loomrail не скачивает template, не устанавливает dependencies, не запускает generated code, не создаёт commit,
remote или push. Откройте готовый каталог в терминале и сами выполните `pnpm install`, затем `pnpm test`. Прерванная
публикация остаётся durable Operation: после reload или restart Settings снова её покажет. Устраните локальный
конфликт и нажмите **Повторить безопасно**; Loomrail не перезаписывает конфликтующие файлы и не удаляет target
автоматически.

### Подключите существующий репозиторий

Откройте **Настройки → Проекты → Подключить локальный репозиторий** и укажите абсолютный путь к корню
репозитория. Подкаталог, относительный путь, не-Git каталог или репозиторий без первого commit отклоняются — Loomrail
не пытается угадать намерение.

Перед первой агентской стадией Loomrail:

1. записывает текущий `HEAD`;
2. создаёт один carry-in snapshot commit из tracked-изменений и untracked-файлов, которые Git не игнорирует;
3. создаёт ветку `loomrail/...`;
4. добавляет linked worktree внутри data directory Loomrail.

Ваш текущий checkout, индекс и активная ветка остаются нетронутыми. При этом общая Git metadata репозитория меняется:
появляются bookkeeping worktree, ветка Loomrail, snapshot commit и недостижимые объекты, возникающие при чтении
изменений. Не регистрируйте репозиторий, незакоммиченные или untracked-файлы которого нельзя показывать выбранному
агенту.

Worktree защищает два задания от случайной записи в один checkout. Он не ограничивает права процесса на уровне ОС и
доступ к сети. Перед живым запуском на чувствительном коде прочитайте [threat model](../security/THREAT-MODEL.md).

### Проверьте и примите Конституцию проекта

После регистрации откройте **Настройки → Конституция проекта**. Первое сканирование работает в read-only режиме и
имеет жёсткие лимиты: оно проверяет только разрешённые root metadata, CI workflows и архитектурную документацию, не
читая исходный код, environment-файлы, содержимое lockfile или тела scripts. Если источник пропущен или достигнут
лимит, scan показывает предупреждение.

Оставьте предложенный preset или выберите другой, затем проверьте все семь разделов и подписи источников. Loomrail не
пишет ничего в репозиторий до действия **Принять и опубликовать**. Принятие создаёт версионированное решение владельца
и публикует `.loomrail/constitution.md` через compare-and-set запись. Если target изменился после scan, публикация
завершается отказом и не перезаписывает файл владельца; сначала повторите scan или разберите конфликт.

Конституция — долговечная политика проекта, а не provider transcript. Замена создаёт новую версию и сохраняет прошлое
решение в audit history.

## 5. Живая работа и её проверка

Установите CLI провайдера и войдите в него, откройте **Настройки → ИИ-провайдер**, выберите **Авто** или конкретного
provider и нажмите **Проверить снова**. Убедитесь, что панель показывает нужный живой provider и статус **Готов**, затем
создайте задачу в зарегистрированном проекте. Перезапуск Loomrail и дополнительная launch-команда не нужны. Brief и
критерии приёмки — долговечные инструкции, из которых собирается контекст каждой сессии.

Для ограниченного репозитория и точного brief, результат которых можно безопасно удалить после проверки, используйте
[воспроизводимый маршрут Codex](../examples/full-route/README.md).

Откройте задачу во время работы:

- **Workflow** показывает стадии, попытки, provider sessions, checkpoints и заполненность context window;
- **Рабочая область** называет исходный репозиторий, ветку Loomrail, base commit и путь worktree;
- **Изменения** перечисляет файлы, отличающиеся от начального snapshot задачи.

Раскройте текстовый файл, чтобы запросить unified diff. Бинарный файл будет назван, но текстового patch у него нет.
Большие списки и тела явно помечаются как обрезанные. Пустой список означает, что Loomrail успешно измерил неизменённый
worktree; ошибка чтения показывается отдельным отказом.

Загружается и обновляется тело только раскрытого файла. Это поверхность проверки, а не staging или принятие отдельных
hunks. Чтобы сохранить результат, откройте показанный worktree в редакторе и выполните собственный Git workflow. До
этого Loomrail не commit-ил ни одного изменения агента.

Claude Code пока не может завершить такой живой маршрут: он обслуживает Discovery, Plan и Review, но не Implementation
или QA. На неподдержанной стадии Loomrail открывает блокирующий Human Request и не переключается на другого provider
молча.

## 6. Добавление Context7 или другого MCP-подключения

Откройте **Настройки → MCP-подключения**. Context7 уже поставляется с Loomrail: выберите **Проверить встроенный
Context7**, не выполняя команд установки. Проверьте абсолютный Node executable и package entrypoint, отметьте
подтверждение точной команды и одобрите её. Это разрешает только ограниченный capability probe. Нажмите **Проверить
capabilities**, убедитесь, что найдены `resolve-library-id` и `query-docs`, выберите tools, подтвердите их read-only
семантику и выдайте Grant. Подключение получат новые provider sessions через локальный proxy Loomrail; уже запущенная
сессия не изменится.

Context7 обращается к внешнему сервису документации. Не включайте в query secrets, персональные данные, закрытый
исходный код или приватный бизнес-контекст. Loomrail не поставляет Context7 API key и использует anonymous tier.

Ручная форма ниже preset предназначена для уже установленного local stdio MCP server. Укажите один абсолютный
executable, по одному argv-элементу на строку и точные имена read-only tools. Loomrail отклоняет shell/package
launchers, URL, env и secret fields и ничего не скачивает из этой формы. Consent, probe и tool Grant остаются
отдельными шагами.

## 7. Restart и recovery

Каждый запуск создаёт новый browser bootstrap. Старая авторизованная вкладка может сообщить, что локальная сессия
закончилась. Запустите Loomrail снова и используйте новую вкладку или напечатанную ссылку.

Задачи, Events, Decisions, бюджеты, Human Requests, evidence, записи очереди и сведения о workspaces хранятся в SQLite
и переживают restart. Процесс provider, умерший вместе с daemon, не считается работающим. Loomrail согласует прерванную
сессию, сохраняет durable checkpoint/context и либо продолжает очередь, либо показывает **Отчёт о восстановлении** и
действие **Продолжить** для владельца.

При старте Loomrail повторно проверяет worktree задачи. Если каталог исчез, workspace помечается потерянным и не
создаётся заново: новое дерево изменило бы смысл уже записанных ветки и baseline.

## 8. Сохранение и восстановление локального состояния

Data directory по умолчанию:

| Платформа | Каталог                                  |
| --------- | ---------------------------------------- |
| macOS     | `~/Library/Application Support/Loomrail` |
| Windows   | `%LOCALAPPDATA%\Loomrail`                |

Чтобы использовать явный изолированный путь, задайте `LOOMRAIL_DATA_DIR` до запуска. Это удобно для оценки продукта и
резервного копирования.

В каталоге находятся:

- `state.sqlite` и возможные WAL-файлы SQLite;
- `backups/`, если непустой базе потребовался backup перед миграцией схемы;
- `demo-projects/` с материализованными demo-репозиториями;
- `workspaces/` с worktree задач.

Поддержанного online export/restore UI пока нет. Чтобы безопасно сохранить текущую установку:

1. Остановите Loomrail через `Ctrl+C` и дождитесь выхода процесса.
2. Скопируйте или заархивируйте **весь data directory**, включая оставшиеся `state.sqlite-wal` и
   `state.sqlite-shm`.
3. Отдельно создайте backup каждого зарегистрированного внешнего репозитория.
4. Если важна незакоммиченная работа агента, дополнительно скопируйте её из показанного worktree или самостоятельно
   сделайте commit в этом репозитории.

Не копируйте один `state.sqlite` во время работы Loomrail: WAL может содержать committed-состояние, которого ещё нет в
главном файле. Автоматические файлы в `backups/` — страховка миграции, а не регулярный полный backup; внешних
репозиториев в них нет.

Для предсказуемого restore остановите Loomrail, верните весь data directory в тот же путь, верните зарегистрированные
репозитории в исходные пути и запустите Loomrail обычной командой. Связи linked worktree записаны и в data directory,
и в Git metadata исходного репозитория; перенос только одной стороны может сделать workspace потерянным.

## 9. Решение проблем

**Страница сообщает, что локальная сессия закончилась.** Daemon остановился или одноразовая сессия больше не
действует. Перезапустите Loomrail и используйте новую авторизованную вкладку. Reload старой вкладки не создаёт новую
сессию.

**Выбранный CLI provider не найден.** Установите CLI и авторизуйтесь по его собственной инструкции, затем выберите
**Настройки → ИИ-провайдер → Проверить снова**. Дополнительная команда запуска Loomrail не нужна. Явно выбранный
недоступный provider отклоняется без скрытой подмены на Mock; Авто может использовать явно обозначенный Mock fallback.

**Launcher откатился к mock.** Проверьте точное регистрозависимое значение: `MOCK`, `CODEX` или `CLAUDE_CODE`.

**Context7 достиг anonymous limit или просит авторизацию.** Встроенный preset намеренно не содержит secret. Отключите
или отзовите его, если anonymous service вам не подходит; хранение API key в этом релизе не поддерживается. Не
вставляйте key в MCP arguments.

**Проект непригоден.** Верните репозиторий по зарегистрированному абсолютному пути. Для встроенного demo Settings может
предложить **Починить demo-репозиторий**. Loomrail не перенаправляет зарегистрированный владельцем Project в другой
каталог молча.

**Создание нового проекта безопасно остановилось.** Откройте Settings: там восстановится та же Operation с закрытым
error code. Разберите конфликт path, marker, файла или Git и только затем нажмите **Повторить безопасно**. Не удаляйте
marker-bound каталог, пока осознанно не проверите и не сохраните нужные файлы.

**Worktree исчез или не читается.** Используйте путь, ветку и текст отказа из карточки. Loomrail не утверждает, что
неизмеренная работа сохранилась, и не создаёт другой worktree для той же задачи.

**Список изменённых файлов пуст.** Фраза «Эта задача пока ничего не изменила в своём worktree» означает успешное
измерение. Отсутствующий Git, потерянный worktree, неверный baseline и нечитаемый каталог показываются как отдельные
ошибки, а не как пустой список.

## Текущие ограничения pre-alpha

- Пакет в npm имеет статус pre-alpha, desktop installer отсутствует.
- Daemon работает только локально; remote и multi-user режимов нет.
- Provider preference сохраняется для каждого Project; необязательный process-wide override блокирует её до restart.
- Для Claude Code не проверен write path стадий Implementation и QA.
- Loomrail не commit-ит, не squash-ит, не push-ит, не merge-ит и не очищает результат владельца.
- Нет поддержанного online state export, retention UI и переносимого restore workspace.
- Worktree защищает от коллизий, но не является полным security sandbox.

Настройка среды контрибьютора и архитектура описаны в [README](../../README.md), упаковка — в
[release guide](../RELEASE.md).

The task outlives the chat.

Loomrail keeps the brief, allowed actions, requests, evidence, budgets, and final decision in one local record. Agent sessions can stop, restart, or change provider without rewriting the work.

The task, not the transcript.

The Workbench shows current state, the task contract, Human Requests, evidence, and the owner’s decision. Raw provider output stays diagnostic.

What survives a provider session?

Provider output is input. Loomrail’s deterministic model owns workflow state and acceptance.

Brief
Acceptance criteria, workflow version, permissions, and budget.
Human Requests
Questions that need a person stay attached to the task.
Evidence
Changes, review, QA, and durable follow-up work.
Decision
Only the owner accepts the delivery or returns it to work.

What does alpha.2 actually do?

The boundary is part of the product, not release-note fine print.

Available in alpha.2

  • Same-machine browser UI, loopback daemon, and local SQLite state.
  • Deterministic mock, plus bounded Codex and Claude Code adapters.
  • Restart recovery, Human Requests, budgets, evidence, and Decisions.
  • Repository registration and an owner-approved Project Constitution.

Deliberately not claimed

  • Cloud sync, remote access, mobile control, or team accounts.
  • Desktop packaging, automatic updates, or a desktop installer.
  • Automatic commit, push, merge, deploy, or browser execution.
  • A complete operating-system sandbox for live providers.

Where should I start?

Run the mock first. Register a repository second. Connect a provider only after reading the boundary.

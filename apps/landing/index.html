Requirements and alternatives

A delivery route that survives the chat.

Provider messages are inputs. Loomrail owns the workflow state and records each consequential change.

  1. 01

    Define done

    Brief, criteria, permissions, workflow version, and budget become one task contract.

    Output: versioned WorkItem
  2. 02

    Decide at the fork

    Questions and approvals become typed Human Requests and durable Decisions.

    Output: attributable decision
  3. 03

    Inspect the change

    Review and QA attach typed evidence to the acceptance criteria.

    Output: evidence matrix
  4. 04

    Accept as owner

    Done is a separate owner-only event, never a provider claim.

    Output: acceptance package

The board is the index. The task is the cockpit.

Current state stays compact. The contract, criteria, provider sessions, changes, evidence, and owner actions open behind the task.

Durable state
SQLite, restart recovery, idempotent commands, append-only events.
Repository boundary
Per-task worktrees, bounded Constitution scan, owner-approved publication.
Human authority
Explicit requests, budgets, recovery decisions, and final acceptance.

Useful now. Exact about the boundary.

Pre-alpha is a product state, not fine print.

Runtime
Loopback daemon, authenticated browser session, local SQLite state.
Providers
Codex: six stages. Claude Code: Discovery, Plan, and Review.
Git
Task worktrees and change inspection. No automatic commit, push, merge, or deploy.
Platforms
macOS and Windows are blocking. Linux is best effort.
Security
Local-first is not a sandbox. Live agents keep the OS account’s permissions and network.
Distribution
npm package today. No desktop installer, remote mode, cloud sync, or plugins.
